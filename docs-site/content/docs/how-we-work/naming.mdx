O Backstage é a fonte de todos os nomes. Um valor definido nele, como o slug, é copiado para o GitHub, o Slack, a AWS e a instalação, e nunca redigitado. Se outro sistema diverge, o Backstage mostra a divergência, e o valor do Backstage vence.

## O slug e o public ID

| Nome | Regra |
|---|---|
| Public ID | Um por organização, sorteado no cadastro, o mesmo em staging e em production. É a chave da organização em tudo: no cadastro, nos nomes de recurso, nos parâmetros, nos logs, nos alarmes e nas issues. |
| Slug da organização | Até 24 caracteres, só letras minúsculas sem acento, números e hífen; começa com letra e não termina em hífen: `^[a-z][a-z0-9-]{0,22}[a-z0-9]$`. Único entre as organizações. Nunca é chave: trocar o slug não muda recurso nenhum. |
| Identificador do projeto | Sorteado pelo núcleo quando o projeto nasce, único na organização, e nunca muda. |
| Slug do projeto | A mesma regra do slug da organização, único dentro dela. |

O slug se repete **igual** em todo nome que vem dele, sem variante sem hífen ou abreviada. A organização vê o alias, que vem do slug, no login e nos links; o endereço da instalação, pelo public ID, nunca sai do ar.

## Repositórios

| Repositório | Nome |
|---|---|
| O de uma organização | `barte-ai-platform-<slug>`, criado do template `barte-ai-platform` |
| O de um módulo | O nome de código, em minúscula: `gatekeeper`, `chronicle`, `loom`, `tessera`, `shell`, `guild` |
| Todos | Na organização `barte-ai-services` do GitHub |

## Ambientes

Os ambientes de conta são só dois: **`staging`** e **`production`**, escritos assim, por extenso, em todo lugar. A subida na máquina de quem desenvolve é `local`, e não é ambiente de conta.

## Recursos na AWS

| Onde | Forma |
|---|---|
| Recursos de uma instalação | `barteai-<public_id>-<component>[-<part>]` |
| Recursos do control plane | `barte-<thing>` |

Os componentes de uma instalação:

| `component` | O que é |
|---|---|
| `app` | O Shell, a entrada da instalação |
| `auth` | O Identity Manager |
| `flow` | O Workflow Manager |
| `data` | O Data Operator |
| `conn` | O Integration Gateway |
| `base` | A base da instalação, como a boundary e os papéis do bootstrap |

O ambiente e a organização vão nas tags do recurso, e não no nome.

## Slack

| Canal | Forma | Regra |
|---|---|---|
| Interno | `#interno-fde-<slug>` | O canal do time da Barte com a organização. Recebe os avisos automáticos, como o lembrete de corte. |
| Externo | `#externo-fde-<slug>-barte` | O canal compartilhado com a organização. Nenhum post automático entra nele. |

## Nomes de código e nomes comerciais

Na tela, na documentação e em todo texto que a pessoa lê, aparece o nome comercial. O nome de código fica no código, nos caminhos e nos nomes de repositório.

| Nome de código | Nome comercial |
|---|---|
| `tessera` | Identity Manager |
| `loom` | Workflow Manager |
| `chronicle` | Data Operator |
| `gatekeeper` | Integration Gateway |
| `shell` | Shell |
| `guild` | Guild |
