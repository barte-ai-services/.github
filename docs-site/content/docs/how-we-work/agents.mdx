title: Como as IAs seguem o handbook
description: Cada repositório carrega no AGENTS.md um bloco gerenciado que aponta para o handbook, e o ci confere que ele está em dia.
---

Toda IA que trabalha num repositório da Barte segue este handbook. O mecanismo tem quatro peças, e nenhuma delas duplica o texto do handbook.

## 1. O bloco no `AGENTS.md`

Cada repositório tem no `AGENTS.md` um bloco gerenciado, entre os marcadores `<!-- barte:handbook:start -->` e `<!-- barte:handbook:end -->`. Ele diz que o repositório segue o handbook, que o handbook vence em conflito, exceto por um ADR do próprio repositório, e resume as regras em uma linha cada:

| Regra | Onde está |
|---|---|
| Plano primeiro, aprovado numa issue de plano | [Issues](/how-we-work/issues#a-issue-de-plano) |
| Toda issue com critérios `AC-n`, cada um nomeado por um teste | [Issues](/how-we-work/issues#rastreabilidade) |
| A agência do Ahrena constrói | [A agência](/how-we-work/agency) |
| O Workflow Manager (Loom) é o único orquestrador | [Workflows](/specifications/workflows) |
| Dados passam pelo Data Operator; processos duráveis e de alta carga, e todo workflow, pelo Workflow Manager; Airflow só para paralelismo dentro de um pipeline de dados | [Dados](/specifications/data) e [workflows](/specifications/workflows) |
| O Identity Manager é o único login | [Autenticação](/specifications/auth) |
| O `ci` é o único check obrigatório, com auto-merge | [Pull requests](/how-we-work/pull-requests) |
| A review é automática, pelo Argos | [Review automática](/how-we-work/review) |
| A documentação vai no PR | [Documentação](/how-we-work/documentation) |
| Segurança antes de meta | [Segurança](/how-we-work/security) |
| «Organização», nunca «cliente» | [Como trabalhamos](/how-we-work) |
| O Backstage é a fonte dos nomes | [Nomes](/how-we-work/naming) |
| Bastidores em inglês, pt-BR na tela | [Idioma](/how-we-work/language) |
| APIs, erros, eventos, dados e configuração seguem as especificações do handbook | [Especificações](/specifications) |

A fonte única do bloco é o arquivo [`agents/handbook-block.md`](https://github.com/barte-ai-services/.github/blob/main/agents/handbook-block.md) do repositório `.github`. Ninguém edita o bloco à mão no projeto: ele é copiado dali.

O `CLAUDE.md` do repositório importa o `AGENTS.md` (`@AGENTS.md`), e assim o Claude Code, o Codex, o Cursor e qualquer agente que lê o `AGENTS.md` recebem o mesmo bloco.

## 2. O Forge instala

O **Barte Forge** instala o bloco ao instalar o Ahrena no projeto, e o reescreve quando a fonte muda. O bloco do Ahrena e o do handbook ficam lado a lado, cada um com os seus marcadores, e o texto do projeto fica fora dos dois.

## 3. O `ci` confere

O job `handbook`, que chama o workflow reutilizável `handbook-check.yml` do `.github`, falha o `ci` quando o bloco falta no `AGENTS.md` ou difere da fonte. Um bloco desatualizado vira um PR vermelho, e não uma IA seguindo uma regra velha.

## 4. O MCP do handbook

O handbook também é um servidor MCP, o `barte-handbook`, para que uma IA o consulte no meio do trabalho em vez de lembrar dele.

| Ferramenta | O que faz |
|---|---|
| `get_rules` | As regras do bloco, com a versão do handbook |
| `list_sections` | As seções e as páginas, com o slug de cada uma |
| `read_page` | Uma página inteira, pelo slug |
| `search` | Busca nas páginas, em pt-BR ou inglês, com e sem acento |
| `check_technology` | O anel de uma tecnologia no [Tech Radar](/specifications/tech-radar), para que serve e como usar |

O servidor só lê e não guarda nada. Ele responde com o que estava na `main` deste repositório no último merge.

O MCP fica atrás do Identity Manager: quem chama apresenta um token do Identity Manager, e o próprio servidor valida o token, sem proxy na frente. Ele não tem entrada pública.

<Callout>O MCP do handbook ainda não está no ar ([barte-ai-services/.github#21](https://github.com/barte-ai-services/.github/issues/21)). Até lá, a consulta é pelo site.</Callout>

## O que fica onde

| Onde | O quê |
|---|---|
| `barte-ai-services/.github` | O handbook, a fonte do bloco, os arquivos de comunidade, os issue forms e o modelo de PR, os labels, os workflows reutilizáveis e os modelos de workflow |
| Barte Forge | A instalação no projeto: o Ahrena e os plugins da Barte, o bloco do handbook no `AGENTS.md`, o MCP do handbook no `.mcp.json` e os workflows que chamam os reutilizáveis |
| Configuração da organização | O ruleset de cada repositório (o `ci` como único check obrigatório) e o auto-merge ligado |
