## Um subagent de documentação em todo trabalho

A sessão que coordena um trabalho de desenvolvimento, seja uma issue, um PR ou uma decisão, abre desde o começo um subagent que documenta ao lado dela. O subagent escreve enquanto o trabalho acontece, e não depois.

## O PR leva a documentação dele

Uma mudança de comportamento, de tela, de arquitetura, de acesso ou de decisão que não aparece na documentação é trabalho incompleto. A documentação vai no mesmo PR da mudança.

## Onde mora

| O quê | Onde |
|---|---|
| A documentação do repositório | `docs/`, na árvore de [um repositório, uma forma](/how-we-work/repositories#a-árvore-docs) |
| As decisões | `docs/architecture/decisions/NNNN-<slug>.md`, uma por arquivo |
| O índice das decisões | `docs/decisions.md` |
| O site | `docs-site/`, na casca `docs-template` |

### O site

O site de um projeto é feito com a casca [`docs-template`](https://github.com/barte-ai-services/docs-template) da Barte: Fumadocs estático, com uma aba por público e a marca padrão. Este handbook usa a mesma casca. Um repositório que ainda publica com outra ferramenta migra para ela.

| Aba | Para quem | O que cobre |
|---|---|---|
| Executivo | A direção da organização | Os marcos, o status e o valor entregue |
| Operação | Quem usa no dia a dia | As telas, as jornadas, as exceções e o glossário |
| Técnico | O time de TI | Arquitetura, decisões, como rodar, configuração e testes |

## Os ADRs

Uma decisão que alguém vai questionar depois vira um ADR. Uma alternativa rejeitada que volta a ser proposta também.

| Regra | O que diz |
|---|---|
| O arquivo | `docs/architecture/decisions/NNNN-<slug>.md`: quatro dígitos e um slug em inglês, kebab-case. |
| A citação | `ADR-NNNN`, no código, nas issues e nos outros repositórios. |
| O número | Não muda nunca. Quem cita a decisão cita pelo número. |
| O idioma | Os títulos das seções em inglês; o texto em pt-BR. |
| Imutável | Um ADR aceito não se reescreve. Um ADR novo altera ou substitui o antigo, e os dois registram isso. |
| O índice | Todo ADR entra no `docs/decisions.md`, com o número, o título e o status. |
| Onde mora | A decisão de um módulo fica no módulo. Outro repositório cita o ADR, sem copiar. |

Os metadados vêm numa lista no topo:

```md
# ADR-NNNN: <the decision, as a sentence>

- **Status:** proposed | accepted | superseded | rejected
- **Date:** YYYY-MM-DD
- **Issue:** #<n>
- **Supersedes:** ADR-NNNN
- **Superseded by:** ADR-NNNN

## Context
## Decision
## Consequences
## Alternatives considered
```

`Supersedes` e `Superseded by` só entram quando valem.

## Os nomes na tela

No site e nas telas aparecem só os nomes comerciais dos módulos da plataforma. Os nomes de código ficam no código ([nomes](/how-we-work/naming)).
