A Barte trata dados pessoais conforme a **Lei Geral de Proteção de Dados** (Lei nº 13.709/2018). A LGPD é a única norma que este handbook trata. A Barte não declara aqui nenhuma certificação.

A conformidade entra no desenho, não depois: cada regra abaixo vale desde a primeira versão de um sistema.

## Minimização

- **Coletar só o dado necessário** para a finalidade, e nada a mais.
- **Uma integração traz só os campos que usa.** A resposta de um provedor é reduzida antes de seguir; se não dá para reduzir com segurança, ela é recusada ([erros](/specifications/errors/catalog)).
- **Dado pessoal não aparece em log, em URL nem em mensagem de erro** ([observabilidade](/specifications/observability)).

## Finalidade

- **Todo dado pessoal tem uma finalidade conhecida**, escrita na documentação do componente que o trata.
- **O dado não é usado para outra finalidade** sem que isso seja decidido e escrito antes.
- **Dado pessoal só chega a um modelo pelo AI gateway**, como todo acesso a modelo ([tech radar](/specifications/tech-radar)).

## Retenção

- **Todo dado pessoal tem prazo de guarda**, escrito junto da finalidade.
- **No DynamoDB, a expiração usa o atributo `ttl`**, em segundos de época ([dados](/specifications/data)).

## Direitos de quem é dono do dado

A pessoa a quem o dado se refere pode pedir para confirmar o tratamento, acessar, corrigir e eliminar os seus dados. Na engenharia, isso quer dizer:

- **o sistema encontra os dados de uma pessoa** pelos identificadores que guarda;
- **o sistema exporta e corrige** esses dados sem trabalho manual no banco.

## Acesso

- **Só alcança um dado pessoal quem precisa dele** para a tarefa, com o menor escopo ([segurança](/how-we-work/security)).
- **O dado circula só por canais cifrados**, e fica cifrado onde é guardado.

## Um problema de conformidade

Um vazamento ou um problema de conformidade nunca vai para uma issue pública. Siga o processo de [segurança](/community/security).
